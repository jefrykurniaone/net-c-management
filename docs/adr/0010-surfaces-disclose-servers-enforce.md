# A surface discloses what the server will refuse and never enforces the rule itself

Every write in this product is refused or allowed by a route handler. The surfaces that lead to those writes therefore have a choice about how to represent a refusal, and the same choice recurs on the Members register, the Sessions register, the Session edit form and both Payment decision dialogs. The decision, taken across those surfaces and recorded here so it stops being re-argued file by file, is that a surface draws the refusal and never performs it.

That resolves into four concrete treatments. **A control whose write the server would always refuse is absent, not disabled.** An Owner row renders none of the account controls, because the server refuses every write to an Owner account (`docs/owner-role-immutability.md`, rule 1); a Completed Session renders neither Cancel nor Reopen; a Session with money behind it renders no Delete. A disabled control advertises a job that cannot be done, and absence is what makes a row read as immutable or closed rather than as merely locked. **A field whose value is frozen is read-only, not disabled.** Its value still posts, it stays focusable and copyable, and a screen reader announces it as read-only instead of skipping it; the design system's read-only treatment comes from the shared `Input`, not from a caller class.

**A condition the Admin may proceed past is a warning, never a block.** The Confirm dialog says in plain words when an amount is short of the Activity's Dues or the Session's Fee, and then lets the Admin confirm anyway. Admins take partial transfers and cash top-ups today; a dialog that refused a short amount would not stop them accepting the money, it would teach them to type a figure that matches, and the ledger would start recording money that was never sent. **A condition the surface can refuse cheaply is refused with a sentence, not with a dead button.** The Reject dialog refuses an empty reason with a message rather than by disabling Reject, because a disabled control explains nothing; the route refuses it too, so the dialog is the courtesy and the route is the rule.

Every one of these disclosures is a condition the primary label defers to, so it renders at Body size in Secondary Ink rather than as a caption, and the button points at it with `aria-describedby` (DESIGN.md, Actions). A condition that reaches only sighted readers, in fine print, is not disclosed.

Status: accepted, 2026-09-04.
