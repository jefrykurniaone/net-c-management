# No-Show is a fourth attendance value, not a rename of the stored "absent" one

The attendance status enum had three usable values, and the one stored as `ABSENT` was carrying two meanings at once: the glossary's **Opted Out** (a Participant held a Seat and withdrew — their own choice) and, in practice, "did not turn up", which the glossary calls **No-Show** and defines as differing from Opted Out in exactly one way: nobody decided. We added a fourth value, `NO_SHOW`, rather than renaming `ABSENT` to something that reads as Opted Out and inventing a new name for the failure case: renaming a stored enum value threaded through attendance, capacity, the monthly-rejection cleanup, the Session export and both dictionaries is a large, risky, purely cosmetic migration, and the glossary plus the i18n copy already carry the correct words — `ABSENT` surfaces as "Opted Out" / "Batal Ikut" and never as "Absent". `NO_SHOW` deliberately does not join the seat-holding pair (`REGISTERED`, `PRESENT`), so every capacity figure is unchanged by definition rather than by adjustment, and it falls outside the monthly-rejection cleanup's `status: 'REGISTERED'` filter by construction, so recording history never makes it deletable. It is written **only** where an Admin sets it explicitly (`ADMIN_SETTABLE_STATUSES` in `src/app/api/sessions/[id]/attendance/manual/route.ts`, which still excludes `MAYBE`); nothing derives it from "the Session ended and the row is still Registered", because that inference would brand a member a No-Show for an Admin's forgetting to take attendance, and the absence of a decision is precisely what the state means. It renders as the **Hollow** mark, which the design system shipped without a producer; this value is that producer. The decision-ID series that appears in code comments (`AD-`, `FR-`, `NFR-`, `OBS-`, `UX-DR`, `BUG-`) refers to a requirements document that lives outside this repository — those are not ADRs, they are left exactly as they are, and this repository's ADR numbering starts at 0001 independently of them.

Status: accepted, 2026-08-29.
