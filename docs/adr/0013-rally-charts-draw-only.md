# Rally's charts draw only, and a series is never drawn straight onto the page ground

Four charts ship in this product: the member dashboard's attendance sparkline (#172), and the admin dashboard's dues-collection bars (#170), money-by-activity donut (#171) and seats-filled line (#171). Each one is paired with a resolver of its own under `src/lib/` — `attendance-sparkline-view.ts`, `dues-collection-view.ts`, `money-by-activity-view.ts`, `seats-filled-view.ts` — and each resolver has a test beside it. Every figure, every colour and every string arrives at the component already finished. A chart component never sees a Payment, a Session, an Attendance row, a Dues Rate or the dictionary, and it derives nothing. The point of the split is where a wrong number surfaces: it is a resolver test's failure rather than something a member or an Admin reads off a dashboard and believes.

**A series is never drawn straight onto the page ground.** Every chart composes onto `ChartFigure` (#169), which is a card, and which carries the chart's title, its caption and a text list of the same values the marks encode. Two things follow from that and neither is optional. The chart colours do not clear 3:1 against the page ground — they are measured against the card face (DESIGN.md, *Chart series*) — so a series drawn outside a card is drawn at a contrast nobody checked. And the text list is the accessibility contract every Rally chart keeps: the figures are readable as text whether or not the marks are, which is also why a chart is allowed to hide its axes without losing detail.

**Colour is allocated across a page, not per chart.** `chartColor(0)` is PBP Green, the strongest-contrast pair in the ramp at 6.56:1 light and 7.54:1 dark, and it is spent on the member dashboard's sparkline because that is the only chart on that page — there is no adjacent series for it to be confused with. The admin dashboard carries three charts at once, so it is allocated differently: the seats-filled line takes `--chart-2`, purple, at 5.34:1 light and 6.80:1 dark. A one-pixel stroke has the least area of any mark to carry its contrast, so it takes one of the stronger pairs; and purple is neither the green the dues chart spends on collected money nor the Orange-to-Dark-Red the donut spends on Activities, so nothing on that dashboard reads as the same series twice.

**Three facts about Recharts 3.8 are relied on here, and are recorded because a version bump can change them.** Motion: `isAnimationActive` defaults to `'auto'`, which respects `prefers-reduced-motion` and disables the grow-in during server rendering. Every chart leaves it at the default rather than pinning it, so the honouring cannot be switched off by accident. Legend order: Recharts reorders a `Legend`'s own payload by each series' translated name, which made the Indonesian dues legend read Owed before Collected although the JSX always declares `collected` first (#224). Legend existence: Recharts only computes a payload at all when the chart mounts an actual `<Legend>`, and a `Pie`'s colour key never does (#215). So `ChartLegendContent` takes its `items` explicitly and the order is the array's — `duesLegendItems(view)` pins Collected before Owed, unaffected by which name string is longer or sorts first in either locale. The shared legend row wraps, so it no longer overflows 390px at four Activities.

**Four per-chart choices are deliberate rather than incidental.** `connectNulls` is pinned `false` on the seats-filled line — Recharts' own default, pinned rather than assumed, because the whole point of a missing point is that it is missing: a week with no Sessions is drawn as a gap, and bridging it would draw a line through a week that never happened and interpolate a fill rate for it. Dots stay on, so a single week between two quiet ones is still visible with no segment to sit on. The line is straight between weeks and never splined, because a week is a discrete measurement and a curve would invent a Tuesday value between two Mondays. The sparkline hides both axes, which drops the tick labels and the reserved axis gutter and leaves the line and its dots in a 64px strip — it sits in the dashboard's stats area rather than an insights region, and the eight-week detail it appears to lose is exactly what the text list and the tooltip carry. And the donut's centre total is HTML rather than an SVG label: the ring is the only thing in its `PieChart` and `PieChart` centres a pie in its own plot area, so an absolutely-positioned overlay lands exactly on the hole, which buys the product's real type roles — `type-figure` is the role every Rupiah amount in this app takes — instead of an SVG `<text>` that would have to restate them.

This record decides nothing about which charts exist or what they measure; those are the specs the issue numbers above name. It decides only what a chart component is allowed to do, where a series may be drawn, how colour is allocated across a page, and which Recharts behaviours are being leaned on.
