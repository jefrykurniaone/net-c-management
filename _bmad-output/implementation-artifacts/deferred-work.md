# Deferred Work

Items surfaced during reviews that are real but intentionally not actioned now. Each notes where it should be picked up.

## Deferred from: code review of story-1.4 (2026-06-30)

- **3-digit hex foreground edge case** — `parseHex` in `src/components/ekskul/ekskul-badge.tsx` accepts only 6-digit hex; a 3-digit hex (e.g. `#fff`) returns null and falls back to a white foreground, which is unreadable on a light background. Not currently reachable (`Ekskul.color` is set via a 6-digit color picker). Expand to accept 3-digit hex during the Epic 4 UI refresh.
- **Badge icon sizing** — `EkskulBadge` (`src/components/ekskul/ekskul-badge.tsx`) renders its lucide icon at the default size (24px) with no explicit `size`, which may look oversized inside a small badge. Visual-only; tune during the Epic 4 UI refresh.

## Deferred from: code review of story-2.1 (2026-07-01)

- **RLS policy script not idempotent** — `prisma/rls-policies.sql` uses `CREATE POLICY "deny_direct_api_access" ON "ActivitySession"` (and the other tables) with no `DROP POLICY IF EXISTS`. After the in-place `ALTER TABLE RENAME`, the pre-existing policy carries onto the renamed table, so re-running the script (Story 2.1 AC3's "re-apply the policy SQL" step) errors `policy … already exists` and aborts the batch. Pre-existing pattern across every policy in the file, not introduced by the rename. Add `DROP POLICY IF EXISTS …` guards when the RLS policies are next hardened / applied to a Supabase (prod) DB that carries the `anon`/`authenticated` roles.
- **Migration ledger drift** — the only migration `prisma/migrations/20260627175208_init/migration.sql` still `CREATE TABLE "BadmintonSession"` (+ index + `Attendance_sessionId_fkey`) and still creates the now-removed `PlayPosition`/`PlayerLevel` enums and `User` columns; no follow-up migration exists. The rename was applied via `ALTER TABLE` + `db push`, so the team's db-push flow is correct, but any provisioning via `prisma migrate deploy`/`migrate reset`/CI would build a `BadmintonSession` table that mismatches the client and fail every `prisma.activitySession.*` query at runtime. Out of Story 2.1 scope by design (AR-9: schema evolution via `db push`, pre-launch; `migrations/**` is immutable). Pick up if/when the team switches to migration-based provisioning or does a prod cutover — regenerate a baseline migration from the current schema.
- **Non-identifier `badminton` residue** — seed/demo data and illustrative comments still contain "badminton": `prisma/seed.ts` (demo ekskul name/slug `badminton`, `communityName 'Xclub Badminton'`), `prisma/backfill-ekskul.ts` (same), `prisma/schema.prisma` comments (`slug` example `"badminton"`, "e.g. Badminton, Music"). Story 2.1 AC4's identifier intent (zero model/type/route/accessor/variable hits) is met; this residue is seed data + comments, disclosed in the story's Completion Notes. Clean up as part of a seed/rebrand follow-up (relates to Epic 1 activity-agnostic rebrand).
