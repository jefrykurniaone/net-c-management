# A rule a route enforces and a client reflects lives in a module that imports neither `server-only`, Prisma nor React

Most of the rules in this product are enforced twice over. `PATCH /api/sessions/[id]` refuses an edit to a Session that money is behind, and the edit form greys the fee field out before the Admin can try. The Dues route accepts a change only for a Period that has not arrived, and the Period picker offers only those Periods. A read-only control is a courtesy and the refusal is the rule, but the two have to agree, and the only way they agree for certain is by being the same function. A rule that sits behind a server boundary cannot be read by the control, so it gets copied into the control instead, and the copy drifts the first time one side is edited. This record fixes where such a rule lives: in a module free of `server-only`, free of Prisma, and free of React, imported by the route and by the component alike. `src/lib/session-lock.ts`, `src/lib/dues-rate.ts`, `src/lib/billing-period.ts`, `src/lib/admission.ts`, `src/lib/payment-price.ts`, `src/lib/public-copy.ts`, `src/lib/attendance-admin.ts`, `src/lib/proof-upload-cases.ts`, `src/lib/session-standing.ts`, `src/lib/chart-weeks.ts` and `src/lib/board-days.ts` are all this shape, and each of them says so in one line rather than restating the argument.

**No clock.** `now`, or the Billing Period, is always a parameter. Two things follow from that, and both are the point rather than a side effect. A test can put the caller in any month, which is what makes the boundary cases — the Period that has just arrived, the Session whose WIB day has just passed — assertable in the Node environment the suite runs in rather than inferable from a page. And the caller passes the *server's* instant, never the browser's: a picker built from an Admin's own laptop clock would offer a month the route then refuses, so the surface must be told what the server thinks the time is instead of deciding for itself.

**No database, and a rule is never enforced only in a `where` clause.** Which rows count is a domain rule — the Seat-holding Attendance statuses, the Cancelled Sessions a fill rate excludes, the `PRESENT` rows an attendance count is made of — and a rule that lives only in a Prisma query is a rule no unit test reaches. The loaders therefore fetch the window wide and hand plain records to the pure module, which does the excluding. `src/lib/insights-data.ts` is the pattern: each loader queries the window its chart is about and adds, multiplies and excludes nothing.

**What a pure module cannot do, it hands back rather than does.** Telling an operator that an Activity has no rate covering a Period, or that a Fee carries no Session, needs a logger the module does not have. Those cases come back as data — `DuesCollectionSeries.skipped`, `MoneyByActivitySeries.unplacedFees` — for the loader to log, which has the second effect of making the skip assertable in a test instead of visible only in a log line.

**The exception is consuming another rule, never restating one.** `src/lib/dues-collection.ts` is not free of `server-only`, because `resolvePaymentMode` lives behind that marker and consuming the single copy of the payment-mode rule matters more than being importable from a browser that has no need of it — the chart component is handed a finished series. The rule this record states is that a rule has one home; a module that reaches for that home and pays a server boundary for it is obeying the record, not breaking it. A module that copies the rule to stay pure is breaking it.

Type-only imports do not count against any of this: they are erased at compile time, so reading the shape of a `server-only` module's output — as `src/lib/session-floor.ts` reads a quota's — does not drag that module into a client bundle. How the generated Prisma enums are imported and written under this rule is `docs/adr/0009-prisma-enums-as-types.md`.
